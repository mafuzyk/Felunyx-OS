# Felunyx OS Vision

## The promise

Felunyx OS should feel like a place someone deliberately chose to stay.

It is not meant to win a benchmark screenshot, imitate a familiar commercial desktop, or accumulate every Linux feature behind a new coat of paint. It should reduce the friction between a person and their computer while preserving the freedom, inspectability, and adaptability that make Linux valuable.

Felunyx is successful when the desktop feels authored, the system feels understandable, and change feels safe enough that the user can explore without treating every update as a gamble.

## The problem

Desktop Linux offers excellent components but frequently exposes their seams:

- settings are scattered across unrelated tools;
- package sources behave like separate worlds;
- recovery is powerful but often inaccessible until the user already understands the failure;
- customization can be deep but brittle;
- polished distributions sometimes hide technical reality instead of presenting it clearly;
- familiar interfaces can become derivative rather than genuinely coherent;
- rolling releases provide freshness but often delegate risk assessment entirely to the user.

Felunyx does not try to eliminate complexity. It organizes complexity so that the person can see, understand, and control it.

## Intended audience

Felunyx is for people who want:

- a visually distinctive Linux desktop with strong defaults;
- a rolling system that treats recovery as a normal capability;
- a complete graphical path for official functionality;
- technical details when they matter, without requiring terminal-only rituals;
- deep customization that remains structured and reversible;
- a comfortable daily system rather than a permanent configuration project;
- a migration path from Windows or macOS without a visual clone of either.

Advanced users remain first-class citizens, but expertise is not an admission requirement.

## Product outcomes

A mature Felunyx installation should provide the following experience:

### Immediate comfort

The installer, first boot, panel, launcher, settings, applications, and recovery environment share one visual and conceptual language. Defaults are useful before customization begins.

### Understandable change

Updates and package operations show their source, scope, dependencies, risk, and expected effects. The system distinguishes routine work from changes that deserve a snapshot or reboot.

### Reversible experimentation

The user can try a desktop layout, Set, package source, update, or system change while retaining a clear path back. Reversibility is designed into workflows instead of advertised as an emergency trick.

### One platform, multiple experiences

KDE Plasma, XFCE, Hyprland, and the future Felunyx Desktop share the Felunyx platform rather than becoming four unrelated distributions with the same wallpaper.

### Authored desktop behavior

Workspaces, Sets, window modes, stacking, session restoration, notifications, and system controls form a coherent workflow. Familiarity is used as an ergonomic tool, never as visual tracing paper.

## Visual identity

Felunyx uses a neutral graphite foundation with restrained blue and violet accents. The visual character is clean, technical, delicate, and slightly ethereal.

It should avoid:

- neon “gamer” styling;
- decorative transparency that harms readability;
- exaggerated cuteness;
- generic enterprise dashboards;
- direct Windows, macOS, GNOME, KDE, or COSMIC imitation;
- visual noise presented as power.

The lynx is the project symbol: alert, quiet, elegant, and independent. The mark should sit between geometric minimalism and expressive stylization.

## Definition of beauty

In Felunyx, beauty is not merely color, blur, iconography, or animation. It is the visible result of good structure:

- controls appear where their effects are understood;
- information density matches the task;
- transitions communicate state;
- recovery looks dependable rather than theatrical;
- related tools share models and vocabulary;
- advanced controls are discoverable without dominating ordinary use;
- every polished surface has a reliable system beneath it.

## Boundaries

Felunyx is not:

- a from-scratch operating system;
- an Arch installer with a theme;
- a compatibility layer that pretends all package ecosystems are identical;
- a promise to fork every upstream project;
- a desktop environment that must exist before the distribution can be useful;
- a beginner mode that removes technical truth;
- an immutable system by default;
- a system that silently repairs, reports, or changes user data;
- a Windows-like launcher with a lynx icon.

## Long-term success

The project has reached its vision when:

- daily tasks are possible through polished graphical interfaces;
- the CLI exposes the same operations and evidence as the GUI;
- risky changes have tested recovery paths;
- desktop profiles feel related but appropriate to their audiences;
- users can explain what an update or recovery action will do before accepting it;
- the native Felunyx Desktop can replace the reference desktop without requiring the platform to be rewritten;
- visual identity survives theme changes because it is encoded in interaction and architecture;
- people stop distro-hopping because Felunyx feels both personal and dependable.
